# 필터, 제목 수정, 빈 목록 안내, 카테고리

## Problem Statement

Todo가 쌓이면 완료된 것과 남은 것이 한 목록에 섞여 지금 해야 할 일을 찾기 어렵다. 제목에 오타가 있어도 고칠 방법이 없어 지웠다가 다시 써야 한다. Todo가 하나도 없을 때는 화면이 비어 있어 앱이 고장 났는지 알 수 없다. 또한 업무·공부·집안일처럼 성격이 다른 Todo를 구분할 방법이 없어 한 목록에 모두 섞인다.

## Solution

Todo 목록을 전체 / 남은 것 / 완료 중에서 골라 볼 수 있게 한다. Todo 제목을 더블클릭해 바로 수정할 수 있게 한다. 보여줄 Todo가 없으면 상황에 맞는 안내 문구를 보여준다. 사용자가 직접 만든 카테고리로 Todo를 분류하고, 카테고리별로 모아 볼 수 있게 한다.

## User Stories

1. As a 사용자, I want 전체 / 남은 것 / 완료 필터 버튼, so that 지금 보고 싶은 Todo만 볼 수 있다
2. As a 사용자, I want 앱을 처음 열 때 "전체"가 선택되어 있기를, so that 아무것도 숨겨지지 않은 상태로 시작한다
3. As a 사용자, I want 현재 선택된 필터가 눈에 띄게 표시되기를, so that 지금 어떤 목록을 보는지 헷갈리지 않는다
4. As a 사용자, I want "남은 것" 필터에서 Todo를 완료하면 목록에서 바로 사라지기를, so that 남은 일만 깔끔하게 볼 수 있다
5. As a 사용자, I want "완료" 필터에서 체크를 해제하면 목록에서 사라지고 남은 할 일에 포함되기를, so that 되돌리기가 자연스럽다
6. As a 사용자, I want 필터를 바꿔도 "남은 할 일 개수"가 항상 전체 Todo 기준으로 표시되기를, so that 필터에 따라 숫자가 달라 혼란스럽지 않다
7. As a 사용자, I want 필터가 켜진 상태에서도 새 Todo를 추가할 수 있기를, so that 입력창이 항상 같은 자리에서 동작한다
8. As a 사용자, I want Todo 제목을 더블클릭하면 입력창으로 바뀌기를, so that 오타를 바로 고칠 수 있다
9. As a 사용자, I want 수정 중 Enter를 누르면 저장되기를, so that 마우스 없이 끝낼 수 있다
10. As a 사용자, I want 수정 중 Esc를 누르면 원래 제목으로 취소되기를, so that 실수로 바꿔도 되돌릴 수 있다
11. As a 사용자, I want 수정 중 입력창 밖을 클릭하면 저장되기를, so that 저장 버튼을 따로 찾지 않아도 된다
12. As a 사용자, I want 제목을 빈 칸으로 만들고 저장하면 수정이 취소되고 원래 제목이 유지되기를, so that 제목 없는 Todo가 생기지 않는다
13. As a 사용자, I want 제목 앞뒤 공백이 저장 전에 제거되기를, so that 추가할 때와 수정할 때 규칙이 같다
14. As a 사용자, I want 제목을 수정해도 완료 여부와 생성 시각이 그대로이기를, so that 수정이 다른 정보를 망가뜨리지 않는다
15. As a 사용자, I want 수정한 제목이 새로고침 후에도 남아 있기를, so that 저장이 믿을 만하다
16. As a 사용자, I want 수정한 Todo의 목록 순서가 바뀌지 않기를, so that 항목이 갑자기 움직이지 않는다
17. As a 사용자, I want Todo가 하나도 없을 때 "할 일이 없어요. 하나 추가해 보세요!" 안내를 보기를, so that 앱이 정상이고 무엇을 할지 알 수 있다
18. As a 사용자, I want "남은 것" 필터에서 보여줄 게 없을 때 "남은 할 일이 없어요!" 안내를 보기를, so that 모두 끝낸 상태임을 알 수 있다
19. As a 사용자, I want "완료" 필터에서 보여줄 게 없을 때 "완료한 할 일이 없어요" 안내를 보기를, so that 목록이 비어 있는 이유를 알 수 있다
20. As a 사용자, I want 안내 문구가 Todo가 생기면 바로 사라지기를, so that 목록과 안내가 겹치지 않는다
21. As a 사용자, I want 존재하지 않는 Todo를 수정하려는 상황(다른 탭에서 이미 삭제됨 등)에서도 앱이 오류 없이 동작하기를, so that 화면이 멈추지 않는다
22. As a 개발자(미래의 나), I want 필터, 제목 수정, 카테고리가 기존 저장 모듈의 async 함수 규칙을 따르기를, so that 나중에 Turso로 바꿀 때 화면 코드를 고치지 않아도 된다
23. As a 사용자, I want 카테고리를 직접 만들 수 있기를, so that 내 생활에 맞는 분류(업무, 공부 등)를 쓸 수 있다
24. As a 사용자, I want 카테고리 이름의 앞뒤 공백이 제거되기를, so that 같은 이름이 공백 때문에 다르게 취급되지 않는다
25. As a 사용자, I want 빈 이름의 카테고리는 만들어지지 않기를, so that 이름 없는 분류가 생기지 않는다
26. As a 사용자, I want 이미 있는 이름(대소문자 구분 없이)으로는 카테고리를 만들 수 없기를, so that 중복 분류로 헷갈리지 않는다
27. As a 사용자, I want Todo를 추가할 때 입력창 옆 드롭다운에서 카테고리를 고르기를, so that 추가와 동시에 분류할 수 있다
28. As a 사용자, I want 드롭다운의 기본값이 "미분류"이기를, so that 카테고리를 고르지 않아도 Todo를 추가할 수 있다
29. As a 사용자, I want Todo가 카테고리를 최대 하나만 갖기를, so that 분류 규칙이 단순하다
30. As a 사용자, I want 각 Todo 옆에 카테고리 이름이 작은 라벨로 보이기를, so that 목록에서 어떤 분류인지 바로 알 수 있다
31. As a 사용자, I want 미분류 Todo에는 라벨이 보이지 않기를, so that 화면이 불필요하게 복잡해지지 않는다
32. As a 사용자, I want 제목을 수정하는 상태에서 카테고리도 드롭다운으로 바꾸기를, so that 이미 있는 Todo도 다시 분류할 수 있다
33. As a 사용자, I want 카테고리를 바꿔도 제목, 완료 여부, 생성 시각, 목록 순서가 그대로이기를, so that 분류 변경이 다른 정보를 망가뜨리지 않는다
34. As a 사용자, I want 카테고리 필터(전체 / 미분류 / 각 카테고리)를 고르기를, so that 한 분류의 Todo만 모아 볼 수 있다
35. As a 사용자, I want 카테고리 필터가 기존 상태 필터(전체/남은 것/완료)와 함께 적용되기를, so that "업무이면서 남은 것"처럼 조합해서 볼 수 있다
36. As a 사용자, I want 카테고리 필터도 앱을 열 때 "전체"로 시작하기를, so that 아무것도 숨겨지지 않은 상태로 시작한다
37. As a 사용자, I want 카테고리 필터를 바꿔도 "남은 할 일 개수"가 전체 Todo 기준으로 유지되기를, so that 필터에 따라 숫자가 달라지지 않는다
38. As a 사용자, I want 카테고리를 삭제할 수 있기를, so that 쓰지 않는 분류를 정리할 수 있다
39. As a 사용자, I want 카테고리를 삭제하기 전에 확인창이 뜨기를, so that 실수로 지우지 않는다
40. As a 사용자, I want 카테고리를 삭제해도 그 안의 Todo는 지워지지 않고 미분류가 되기를, so that 할 일을 잃어버리지 않는다
41. As a 사용자, I want 선택 중인 카테고리 필터의 카테고리를 삭제하면 필터가 "전체"로 돌아가기를, so that 존재하지 않는 분류를 보고 있는 상태가 생기지 않는다
42. As a 사용자, I want 카테고리 필터에서 보여줄 Todo가 없을 때도 알맞은 빈 목록 안내가 보이기를, so that 목록이 비어 있는 이유를 알 수 있다
43. As a 사용자, I want 카테고리가 새로고침 후에도 남아 있기를, so that 매번 다시 만들지 않아도 된다
44. As a 기존 사용자, I want 카테고리 기능이 생기기 전에 저장한 Todo가 그대로 보이고 미분류로 취급되기를, so that 업데이트 후에도 데이터가 깨지지 않는다
45. As a 사용자, I want 존재하지 않는 카테고리를 가리키는 Todo(다른 탭에서 이미 삭제됨 등)가 오류 없이 미분류로 보이기를, so that 화면이 멈추지 않는다

## Implementation Decisions

- **저장 모듈**에 제목 수정 함수를 하나 추가한다. 다른 저장 함수와 똑같이 async이며 `id`와 새 제목을 받는다. 대상 Todo가 없으면 아무 일도 하지 않고 오류도 내지 않는다.
- 제목 검증(앞뒤 공백 제거, 빈 제목 거부)은 추가할 때와 같은 규칙을 공유한다. 빈 제목으로 수정하면 저장하지 않고 원래 제목을 유지한다.
- 수정은 `id`, `completed`, `createdAt`을 바꾸지 않는다. 목록 정렬은 지금처럼 `createdAt` 오름차순이므로 순서도 유지된다.
- **필터**는 화면 상태일 뿐이며 저장하지 않는다. 앱을 열 때마다 "전체"로 시작한다. 필터 값은 `all | active | completed` 세 가지다.
- "어떤 Todo를 보여줄지" 계산은 화면 컴포넌트 밖의 순수 함수로 분리한다(입력: Todo 배열과 필터, 출력: 보여줄 Todo 배열). 화면은 이 함수의 결과를 그리기만 한다.
- **남은 할 일 개수**는 필터와 상관없이 전체 Todo 중 완료되지 않은 것의 수로 유지한다. "완료된 항목 모두 삭제" 버튼도 필터와 무관하게 전체 기준으로 동작한다.
- **빈 목록 안내 문구**는 두 가지를 구분한다: 저장된 Todo가 아예 없을 때, 그리고 선택한 필터에 맞는 Todo가 없을 때. 필터별로 문구가 다르다(위 사용자 스토리 17~19).
- 제목 수정 UI는 더블클릭으로 시작하고 Enter/외부 클릭으로 저장, Esc로 취소한다. 한 번에 하나의 Todo만 수정 상태가 된다.
- ADR-0001을 따른다: UI는 `localStorage`를 직접 건드리지 않고, 새 함수도 서버로 옮길 수 있도록 브라우저 전용 타입을 시그니처에 쓰지 않는다.
- 용어집에 "필터"(Todo 목록에서 무엇을 보여줄지 고르는 화면 상태, 저장하지 않음)를 추가한다.
- **카테고리**: 사용자가 만든 이름 붙은 분류. `id`(문자열 UUID)와 `name`을 가진다. Todo는 카테고리를 0개 또는 1개 갖고, 없으면 **미분류**다. 여러 개를 붙이는 "태그"는 다루지 않는다.
- Todo에 `categoryId`(문자열 UUID 또는 null)를 추가한다. 카테고리는 Todo와 **별도 목록**으로 저장한다(localStorage 키 `my-todo:categories`). 이유와 Turso 이전 계획은 ADR-0002에 기록한다.
- 기존에 저장된 Todo에는 `categoryId`가 없으므로, 읽을 때 값이 없거나 존재하지 않는 카테고리를 가리키면 null(미분류)로 취급한다. 별도의 데이터 이전 작업은 하지 않는다.
- **저장 모듈**에 카테고리 조회 / 추가 / 삭제 함수와 Todo의 카테고리를 바꾸는 함수를 추가한다. 모두 async이고 브라우저 전용 타입을 시그니처에 쓰지 않는다. Todo 추가 함수는 선택적으로 카테고리를 받는다.
- 카테고리 이름 규칙: 앞뒤 공백 제거, 빈 이름 거부, 이미 있는 이름(대소문자 구분 없음)은 거부한다. 이름 수정은 하지 않는다(지우고 다시 만든다).
- 카테고리를 삭제하면 그 카테고리의 Todo는 삭제하지 않고 `categoryId`를 null로 되돌린다. 삭제 전에 확인창을 한 번 띄운다. 선택 중이던 카테고리 필터는 "전체"로 돌아간다.
- **카테고리 필터**는 화면 상태이며 저장하지 않는다. 값은 전체 / 미분류 / 특정 카테고리이다. 기존 상태 필터와 **동시에(AND) 적용**한다. "어떤 Todo를 보여줄지" 계산 순수 함수는 두 필터를 함께 받는다.
- 남은 할 일 개수와 "완료된 항목 모두 삭제"는 두 필터와 상관없이 전체 Todo 기준을 유지한다.
- 화면: 추가 입력창 옆에 카테고리 드롭다운(기본 미분류), 각 Todo에 카테고리 라벨(미분류는 라벨 없음), 제목 수정 상태에서 카테고리 드롭다운, 카테고리 필터와 카테고리 추가/삭제 UI를 둔다.
- ADR-0002를 새로 쓴다: 카테고리를 Todo와 별도 목록으로 저장하는 결정.
- 용어집에 "카테고리", "미분류", "카테고리 필터"를 추가하고, "Todo 목록"의 "카테고리 개념은 없다"는 문구를 고친다.

## Testing Decisions

- 좋은 테스트는 내부 구현이 아니라 외부에서 보이는 동작만 확인한다. 저장 모듈은 함수를 호출하고 그 뒤 목록 조회 결과를 확인한다.
- 테스트 경계(seam)는 **저장 모듈의 async 함수 인터페이스 하나**다. 필터 계산 순수 함수도 같은 방식으로 입출력만 확인한다.
- 확인할 동작: 카테고리 추가(공백 제거, 빈 이름·중복 이름 거부), 카테고리 삭제 시 Todo가 남고 미분류가 된다, 카테고리 없이 저장된 기존 Todo와 존재하지 않는 카테고리를 가리키는 Todo가 미분류로 읽힌다, 두 필터를 함께 적용한 결과가 올바르다, 제목 수정이 제목만 바꾸고 `id`/`completed`/`createdAt`/순서를 유지한다, 공백만 있는 제목은 거부된다, 없는 `id`를 수정해도 오류 없이 무시된다, 필터별로 올바른 Todo만 반환된다, 남은 개수는 필터와 무관하다.
- 현재 프로젝트에는 테스트 도구와 기존 테스트가 없다(prior art 없음). 구현 시 테스트 러너(예: Vitest)를 새로 도입하고 `localStorage`는 테스트에서 대체 구현을 사용한다. 화면 클릭 테스트는 하지 않는다.

## Out of Scope

- 필터 선택(상태·카테고리)을 새로고침 후에도 기억하는 것
- 카테고리 이름 수정, 색상, 순서 바꾸기
- 한 Todo에 여러 카테고리(태그)를 붙이는 것
- 순서 바꾸기(드래그), 마감일, 검색, 정렬 옵션
- 수정 취소/실행 취소(undo), 수정 이력
- Turso 전환과 서버 쪽 이동(ADR-0001에 따라 별도 작업)
- 화면(브라우저) 단위 자동 테스트

## Further Notes

- 네 기능 중 앞의 셋은 서로 독립적이라 순서대로 따로 구현해도 된다: 빈 목록 안내 → 필터 → 제목 수정. 카테고리는 데이터 구조(Todo 필드와 별도 저장 목록)가 바뀌므로 마지막에 구현하는 편이 안전하다.
- 필터와 안내 문구가 함께 쓰이므로 필터를 먼저 만든 뒤 안내 문구를 붙이는 편이 쉽다면 순서를 바꿔도 좋다.
