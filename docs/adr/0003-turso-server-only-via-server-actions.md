# 저장소는 Turso를 쓰고, 서버에서만 접근하며, 화면은 서버 함수로만 호출한다

localStorage는 한 브라우저에서만 보여서 폰과 PC가 목록을 공유할 수 없다. 그래서 Todo와 카테고리를 Turso(클라우드 SQLite 호환 데이터베이스)에 저장한다. 접속 주소와 비밀 키는 브라우저에 노출되면 안 되므로 데이터베이스는 서버 코드에서만 열고, 브라우저 화면은 Next.js 서버 함수(Server Action)로만 저장소를 호출한다. 화면이 보는 인터페이스(함수 이름, 인자, 반환 형태)는 ADR-0001에서 정한 비동기 저장 모듈 그대로라서, 화면 로직은 저장소가 바뀌어도 그대로다.

## Considered Options

- 브라우저에서 Turso에 직접 접속: 비밀 키가 브라우저에 노출되어 채택하지 않았다.
- Route Handler(API 경로)로 저장소 호출: 서버 함수와 가능한 일은 비슷하지만, 요청과 응답 형태를 직접 만들어야 해서 이 앱에서는 서버 함수가 더 단순하다.

## Consequences

- 서버 함수는 화면을 거치지 않은 직접 POST 요청으로도 호출될 수 있다. 그래서 모든 서버 함수는 받은 값을 검사하고, Turso에 연결하거나 배포하기 전에 접근 보호(암호)를 반드시 붙여야 한다(티켓 04).
- 클라이언트는 서버 함수를 한 번에 하나씩 순서대로 보낸다. 그래서 변경 함수는 변경 뒤의 전체 목록을 돌려주고, 화면은 그 결과를 그대로 반영한다. 호출이 실패하면 화면의 목록은 바뀌지 않는다.
- 서버 전용 저장 모듈은 로컬 파일 데이터베이스와 Turso를 같은 코드로 연다. 접속 주소를 정하지 않으면 로컬 파일을 쓰므로 자동 테스트와 개발은 인터넷 없이 돌아간다.
- 이전의 브라우저용 localStorage 저장 모듈은 제거했다. 기존 브라우저 데이터를 옮기는 일은 별도 티켓(05)에서 다룬다.
